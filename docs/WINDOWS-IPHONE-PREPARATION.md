# Windows + iPhone 准备清单与自动补齐顺序

> New installations: start with [Universal setup](UNIVERSAL.md) and the [single maintained prompt](UNIVERSAL-PROMPT.md). Detect the actual device/client and any number of sources first. This page documents a specific adapter or the legacy two-source workflow; it is not a universal client/subscription requirement.


本页供目标 Windows 上的本地 Codex 执行。**先检查，复用可用环境，自动补齐已授权的缺项，然后继续电脑与手机配置。** 不把清单全部转交用户手动安装，也不在输出检查报告后结束任务。配套 [执行提示词](WINDOWS-IPHONE-PROMPT.md) 和 [两阶段流程](WINDOWS-IPHONE.md)。

## 用户提前准备的最少内容

- 一台能正常联网、能运行本机命令和读写工作目录的 Windows Codex。云端网页聊天不能代替目标电脑的本地执行环境。
- 一个或多个有效节点来源，明确固定Claude节点及普通池用途；固定节点及预期出口需核实，不要求必须购买住宅。已导入就复用；未导入时由Codex通过本地正式界面/接口协助，不在聊天公开链接或密钥。单来源多节点可显式mixed分配，只有一个节点时先解释普通池约束。
- iPhone、支持数据传输的数据线，以及能在现场解锁和确认系统提示的人。手机暂未连接不阻止电脑阶段。
- 手机若与电脑共用订阅，确认套餐允许多设备同时使用；用量共同计入套餐。不默认手机与电脑是同一份订阅，也不自动购买新套餐。

不用提前手工合并订阅、设置 DNS 或开启 TUN。现有 iOS/App 版本先读取，不为了配置一律升级。

## 软件与依赖：检查后自动处理

| 对象 | 检查内容 | 缺失时的处理 |
|---|---|---|
| 本地 Codex | 本机命令、工作目录读写和现有联网可用 | 这是启动前提；登录、工具访问批准由本人完成；不升级或重启正在执行任务的 Codex |
| 实际代理客户端；Verge/Mihomo仅在识别匹配时 | 安装路径、版本、运行状态、真实配置目录、全部来源及控制接口 | 先复用现有客户端；只有用户选定软件缺失时才从官方来源安装，不默认安装Verge替换其他App。首次启动保留当前上网方式，已运行内核不自动升级/重装 |
| Chrome | 实际安装、版本与企业政策 | 缺失可从官方来源安装；已装复用，不强退浏览器、不绕过企业政策 |
| Claude Desktop | 是否使用桌面端、实际版本/签名与路径 | 用户需要且缺少时从官方来源安装；写设置前保存工作并正常退出；登录由本人完成 |
| 原生 Claude Code | 是否在使用、真实可执行文件和项目设置 | 已安装则配置；未使用则标记 not-needed，不为凑清单额外安装。明确需要时再走官方安装方式 |
| Python | 实际解释器与 OpenSSL；USB工具需 3.11+ | 复用兼容解释器，缺失时安装官方受支持版本；不覆盖别的项目运行时 |
| Node.js | 现有版本是否满足仓库要求 | 复用兼容版本；缺失时安装官方当前受支持 LTS，不更改其他项目锁定的版本 |
| Git / curl.exe | 命令可用性 | 复用现有；缺失时从官方来源补齐，或使用核验过的仓库下载方式。Git 并非必须手工预装 |
| Python依赖 | requirements.txt、requirements-mobile.txt 与实际 venv | 在独立 venv 按仓库固定版本安装；桌面与USB环境可分开，明确解释器路径，不全局 pip install，不盲目升级 |
| Apple Devices / iTunes 设备服务 | USB能否识别；服务状态与已安装组件 | 已有任一可用路径就保留；缺少时优先官方 Apple Devices/Microsoft Store 渠道，必要时按上游说明核对官方 iTunes 组件；不同时堆叠/替换工作中的驱动 |
| iPhone Shadowrocket / Claude | 安装情况和真实版本；前者是手机配置目标 | 通过 App Store 正常安装；商店登录、付费购买、Face ID/密码由本人确认。没有手机界面控制能力时给出最少必要点击 |

这份表是 Codex 的执行流程，不是一个会自动安装所有软件的脚本；`mobile_usb.py doctor` 自身只读检查，不安装组件。桌面和 USB venv 的建立方法见 [WINDOWS](WINDOWS.md)、[WINDOWS-IPHONE](WINDOWS-IPHONE.md)。不使用系统全局 Python 环境，也不覆盖已有 `.venv` 或 `.private/mobile-tools`；先核实，确需另一版本就使用新目录并记录。

## 安装与现有网络的保护顺序

1. **先盘点和保存基线。** 读取已有工作流/备份，记录系统架构、软件版本/路径、当前系统代理/TUN状态、网络和 Codex 是否可用。已有配置通过就复用，只处理缺失或漂移项。不要为了标准化先切模式。
2. **确认当前下载路径。** 安装包与依赖使用现有普通线路或可用直连，不切换整机节点或借用 Claude 住宅套餐。若当前只有住宅才能下载，先记录需要下载的组件与费用边界，再向用户说明并取得该下载许可；不自行跑大测速。
3. **按需安装。** 优先核对已安装项；使用官方安装器或经核对的包管理器来源。WinGet 先 search/show 核对精确包ID、来源、发布者、架构、版本与安装器URL，再用精确匹配安装单个缺项。包名匹配不等于可信来源；适用时核验签名/发布校验值。无 WinGet 时使用官方安装包，不执行陌生安装脚本或在线订阅转换器。
4. **不借安装扩大变更。** 不运行全机 upgrade-all，不自动重装网络驱动、关闭防火墙、修改系统时区、打开热点/开发者模式或重置手机信任。不使用忽略哈希/恶意软件检查或自动重启选项。安装器要求退出工作软件、重启电脑或改变当前联网方式时，先保留进度并说明具体影响，只暂停相关一步；普通依赖安装不要求重复征询同一授权。
5. **安装后重新检测。** 复查实际版本、命令路径、服务/USB能力和原有连通性。命令退出码成功不等于软件已经可用；不要通过重启 Codex 刷新 PATH，优先直接使用已核实的可执行文件路径。
6. **立即继续配置。** 依赖与权限就绪后进入 WINDOWS-IPHONE.md 的电脑阶段，验证后进入手机阶段。需要系统确认时保存当前位置，用户完成后从该处继续，不重跑成功的 apply 或覆盖备份。

只在已授权的目标 Windows 执行安装/配置。更新本仓库不会修改发布者的 Mac 网络。新配置热加载和真实设备测试无法保证零延迟；可能打断正在工作的连接时先安排可接受时段，不为了验收关闭生产 Clash 或改正在使用的住宅节点。可选 TUN 试验继续使用原有独立本地恢复机制。

## 权限：能检查的先检查，必须本人完成的再提示

| 权限或动作 | Codex执行范围 | 本人需要做的事 |
|---|---|---|
| 本机工作目录/终端 | 先做有限范围读写与命令检查，使用既有授权 | 工具确实请求访问时批准本任务所需范围；不要求永久全盘/管理员权限 |
| Windows UAC / 企业管理 | 发起已核实的必要安装；不能绕过UAC或组织政策 | 实际弹窗时确认或请管理员处理；密码不发给Codex |
| iPhone USB连接与信任 | 识别USB指纹、选择明确设备，正常发起pair | 使用数据线、解锁，在手机/Apple Devices提示时信任并自行输入密码 |
| Shadowrocket Documents | probe检查声明与实际共享能力，只读写选定文档 | 需要时通过App正式导出/导入；没有可通用打开的“任意读写App”权限 |
| iOS VPN批准 | 用正式App流程引导，不能代批系统权限 | 出现“添加VPN配置”等提示时自行允许/验证身份 |
| Chrome政策/手机导入界面 | 已有且允许的界面工具可协助，随后读取或实测效果 | 工具不支持或禁止时，完成明确的一次点击，然后继续验证 |
| App商店/服务登录和购买 | 可打开正确入口、读取非敏感状态 | 登录、验证码、购买及付款由本人完成；本授权不包含付费 |

Apple Devices 能显示手机只证明识别成功；Shadowrocket还须支持文件共享。如果不支持，保持电脑配置，使用小火箭的正式导出/导入路径；不提取完整容器/备份、不猜私有数据库。无法自动操作的界面应明确告知具体按钮和目的，不能伪称已经点击或已生效。

## 进度记录与验收

Codex在目标电脑 `.private/` 下保存一份精简准备记录（例如 `preparation.json`）：每项的实际版本/路径、`ready` / `installed` / `needs-user` / `blocked` / `not-needed` 状态、验证时间、证据位置及下一步。不要记录完整环境变量、订阅链接、密码、登录令牌；不提交公开仓库。此记录由执行代理维护，不是现有脚本自动产生的验收证明。

- 当前无法获取关键输入时只暂停相关步骤；手机未连接则先完成电脑，接机后续接。
- 用户确认后重新核验权限/状态，而不是把一句“允许”当作操作已成功。
- 准备检查 → 电脑候选/应用/实际验证 → USB探测/私有候选/传输回读 → 手机正式导入/VPN/实际验证 → 交付恢复方法。
- 软件安装成功、CI通过、文件传输成功与实际DNS/WebRTC/客户端路由是不同证据，分别记录；未接机项仍标未实测。

- [Apple Windows文件共享](https://support.apple.com/en-ie/120402)、[USB识别与信任](https://support.apple.com/en-gb/108643)：设备连接与App共享各自核实。

- [WinGet install](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)、[WinGet show](https://learn.microsoft.com/en-us/windows/package-manager/winget/show)：精确识别安装对象及其元数据。本流程不内置未经核对的产品ID或下载地址。
