# 本地实施、验收与恢复

## 1. 只读盘点

`scripts/manage.py inspect` 不输出订阅链接和认证字段。确认住宅订阅已选中、普通订阅仍有效；从 profiles.yaml 识别真实 UID 和 profile-specific script，不能假定作者机器上的文件名。读取 global merge/script 与 profile merge/script 的执行顺序；最终 runtime 是核验对象，持久脚本才是维护来源。

读取当前 app bundle ID、路径、Clash/Mihomo 版本、TUN/系统代理和本机监听端口。此版本以 Mihomo v1.19.15 的语义为基线。缺少 node/python3/Ruby 或 PyYAML 时先选择目标环境已有的官方运行时；不安装不明二进制、不打印 PATH 中的密钥。

## 2. 两个订阅合并

住宅订阅继续作为基础 profile。扩展脚本注入普通订阅的 HTTP proxy-provider，每个分组显式限制来源。普通 provider 自行更新，不需要激活它的订阅卡片；两份套餐分别计费。

`init` 从本地 profile 元数据取普通订阅 URL，只写 `.private/settings.json`。务必审阅该 URL 对应的账户/套餐确实是普通线路，并检查 provider 节点不混入住宅套餐。仓库无法从“美国”等名字推断供应商实际计费身份。支持节点列表格式的 Clash/Mihomo 订阅；仅含 proxy-providers、没有内联节点的住宅配置需要代理先适配，不自动猜。

选择住宅节点须核对 name/server/port/type 四元组。IP 是公网出口，不是入口 server。若此前有入口重命名修复，选择当前订阅中的真实入口名。用隔离 Mihomo（备用控制端口、TUN关闭、系统代理不改、节点从物理网卡出去）测 `https://www.cloudflare.com/cdn-cgi/trace`，记住明确接受的公网 IP/国家。不得把普通浏览器的 IP 卡片当成 Claude 出口证明。

`proxyServerNameservers` 是**节点域名引导解析**。供应商特殊节点域名可能必须用它自己的 DNS；不能为了“统一DNS”删掉。普通订阅下载默认直连，下载无法直连时需要另行审阅可行引导方式，绝不偷偷用住宅。避免引导DNS依赖其自身代理组形成循环。

## 3. 准备和应用

`prepare` 备份原选中脚本/运行配置，生成候选，运行本机 Mihomo `-t`。候选生成时保留原 TUN 状态及不冲突的监听器。规则与组会被整组替换：如果原系统存在企业网络或其他重要规则，先适配再进行。

隔离测试必须覆盖：住宅正常、住宅入口失败且无普通回退、普通美国正常/美国故障其他地区接管/全部故障、国内请求直连。不要在生产环境停节点或退出 Clash 来验收。仓库 `tests/integration.py` 使用本机假代理验证核心语义，不需要真实订阅，不能替代供应商线路实测。

`apply` 检查备份前哈希与当前选中 profile 索引没变，然后写入脚本与 runtime、通过本地 Unix socket `PUT /configs?force=false` 热加载。不开新的网络扩展、不杀进程。若固定组或住宅出口预检失败，恢复原文件并尝试重新加载；恢复 API 也失败时必须人工检查，不宣称已恢复。端口监听归属、实际连接链与客户端页面仍需代理进一步验证。

订阅刷新后需要再次检查运行配置：GUI设置和后置脚本可能覆盖生成结果。入口缺失/重名被拒绝是正常保护动作；不要加 DIRECT 或自动住宅 fallback 去消除错误。

## 4. 客户端与真实验收

按 CLIENTS.md 配置。记录本轮验证时间和以下状态，报告只在本机保存：

- Claude 客户端页面可加载、专用端口出口与预期相同；Claude域名和下载连接链都是住宅；普通端口的已知Claude进程也归住宅。
- Codex实际 OpenAI 请求与普通站点链为 ordinary-only；ChatGPT非Codex请求为住宅。共享域名的进程识别为空时不能假称已区分。
- 国内请求 DIRECT；不要将所有 Cloudflare/CDN 一概设住宅，否则普通外网会大量消耗住宅套餐。
- 正常请求验证与“故障不直连”验证分开。没有发送聊天消息就只声称页面/连接恢复，不能声称模型回复已测试。
- 测完停止自己启动的隔离进程，保留本地证据；不触碰生产连接，不删除用户资料。

## 5. 回滚

`manage.py rollback --plan .private/plan` 验证备份和应用后哈希，再还原两个文件并热加载。若用户后来又改过配置，工具拒绝覆盖；由代理比较后合并，不能强制旧备份盖掉新工作。客户端变更单独 `clients.py rollback`，先保存工作并正常退出客户端。恢复旧入口可能恢复原来的故障，不保证联网。

## 6. 后续维护

普通provider按周期更新。住宅凭据更新但四元组不变时脚本沿用订阅的新凭据；四元组变化则拒绝。入口或出口变更必须重新测量、明确接受，再更新 `.private/settings.json` 并新建计划。代码升级先本地测试，不能自动覆盖运行环境；本仓库没有后台计划任务。
