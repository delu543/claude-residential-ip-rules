- 9 项 Node 配置测试、12 项 Python 测试通过。新增：ChatGPT 默认普通/住宅显式选择、已启用 TUN 的两种 DNS 传输、浏览器策略备份/并发修改拒绝、Mac 安装器在 Windows 修改前停止。
- 本机 Mihomo 1.19.15 隔离集成通过：普通美国优先、美国失败去其他普通地区、全部普通失败不借住宅、Claude住宅失败不走普通、专用代理关闭后请求失败、本地 DIRECT、ChatGPT 默认普通。
- 本机 Chrome 实测：设置 WebRtcIPHandling 并由用户重新加载政策后，同一页面 9 个国内/海外 STUN 检测全部显示未检测到 IP 泄露，页面 HTTP 出口仍是普通订阅。不是将检测域名改走住宅。未做 Windows 实机测试。
- 系统 DNS UDP/TCP 对 Claude 域名均返回 fake-IP；普通浏览器的 DNS 检测观察到普通节点地区递归解析器，没有观察到本地运营商解析器。这是有范围的样本，不是全部 DNS 永久无泄露证明。
- 住宅网络可用性与防泄露分开验收：节点入站 TCP 不可达时不能把账号暂停归咎于泄露，也不能宣称修复策略已恢复住宅服务。

## 通用化与TUN安装顺序修订

本节取代前版“初始化可直接启用TUN”的默认流程：先检查可用系统代理，默认不启用TUN/不改Chrome DoH。TUN改为可选独立试验，并始终恢复基线；Windows独立进程与假内核命名管道回归验证超时恢复路径，实际网络驱动/远程设备根因仍须现场检查。

回归覆盖：端口占用与复用、普通本地订阅、非VLESS节点、非US出口国家、无Codex、domain-only空正则防护、地区/DNS个性化、Chrome默认无DNS改动、基线失败停止、超时恢复与备份冲突。原住宅失败拒绝/普通跨地区fallback继续用隔离Mihomo验证。模板保留空个人字段，不能直接应用。

Changed Existing Capabilities：端口由默认常量改为自动选择且稳定保存；Windows的TUN/DNS全面验收从安装必需改为后续可选；固定住宅不自动换节点、数据保留和逆序回退不变。
